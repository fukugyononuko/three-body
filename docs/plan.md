# 制作計画書：三体問題シミュレーター（Rust + WebAssembly）

副業のぬこの制作例その 4。3 つの天体が重力で引き合う「三体問題」を、Rust で数値計算し、WebAssembly にしてブラウザで動かす。
見た目は、論文や研究室のページのように飾りの少ないものにする（白い紙に細い線の図。ダークモードにも対応）。

## 1. 目的

| ID | 目的 |
| --- | --- |
| G-01 | 三体問題の面白さ（美しい周期解、予測できないカオス）を、触って確かめられる形で見せる |
| G-02 | 数値計算が「正しい」ことを、検証つきで示す（保存量、既知の解との一致） |
| G-03 | Rust・WebAssembly・Web ページを組み合わせて作れることを見せる |

## 2. 見せるもの（シナリオ）

| ID | シナリオ | 内容 | 出典 |
| --- | --- | --- | --- |
| S-01 | 8 の字の解 | 同じ質量の 3 天体が 8 の字を描いて回り続ける周期解 | Chenciner & Montgomery (2000)、初期値は Simó による |
| S-02 | ピタゴラスの三体問題 | 質量 3・4・5 の天体を、辺の長さ 3・4・5 の直角三角形の頂点に静止させて始める。接近を繰り返したあと、1 つが弾き飛ばされる | Burrau (1913)、Szebehely & Peters (1967) |
| S-03 | カオス（初期値鋭敏性） | 基準の初期値と、指定した天体の位置を指定した量（Δx、Δy）だけずらした初期値の 2 つの計算を重ねて表示し、やがて全く違う動きになる様子を見せる | — |
| S-04 | 積分法の比較 | いま計算している運動の全エネルギーの相対誤差を時系列で描く。同じ初期値・同じ刻み幅で 3 つの積分法を重ねて比べることもできる | — |
| S-05 | 自分で決めた初期値 | 3 天体の質量・位置・速度を入力して計算する（平面内）。S-01、S-02 は入力欄に値を入れるプリセットとして扱う | 利用者の意見（2026-10-11） |

## 3. 数値計算

| ID | 項目 | 内容 |
| --- | --- | --- |
| N-01 | 方程式 | 万有引力（ニュートン）。重力定数 G = 1 の無次元の単位。軟化（ソフトニング）はしない |
| N-02 | 積分法 1 | 古典的ルンゲ・クッタ法（RK4、刻み幅一定） |
| N-03 | 積分法 2 | ドルマン・プリンス法（RK45、刻み幅を誤差に応じて自動で変える） |
| N-04 | 積分法 3 | リープフロッグ法（速度ベルレ法、刻み幅一定、シンプレクティック） |
| N-05 | 保存量 | 全エネルギー、全運動量、全角運動量を計算して表示する |
| N-06 | 刻み幅と許容誤差 | 刻み幅一定の方法（N-02、N-04）は刻み幅 h を、RK45（N-03）は許容誤差を、利用者が選べる |

- 天体が近づくと加速度が急に大きくなるので、刻み幅一定の方法（N-02、N-04）は誤差が増える。これも比較で見せる（S-04）。

## 4. 構成

| ID | 構成要素 | 内容 |
| --- | --- | --- |
| C-01 | 計算部分（Rust） | 外部クレートを使わず、標準ライブラリだけで書く。積分法とシナリオ、保存量 |
| C-02 | WebAssembly の窓口（Rust） | 関数を直接公開し、天体の位置などを共有メモリの配列で渡す（wasm-bindgen などは使わない） |
| C-03 | Web ページ（Astro + TypeScript） | キャンバスに軌道を描く。初期値、積分法、刻み幅・許容誤差、再生速度、カオスのずらし方を選べる。全エネルギーの相対誤差をグラフで表示（軸のラベルは英語） |
| C-04 | 数式 | TeX で書き、ビルドの時に MathML に変換する（Temml）。数式のフォントは STIX Two Math（OFL）を、使う文字だけに絞って配信する |

公開先：`https://fukugyononuko.github.io/three-body/`（GitHub Pages）

## 5. 品質

| ID | 基準 |
| --- | --- |
| Q-01 | Lighthouse の性能・アクセシビリティ・ベストプラクティス・SEO が 90 点以上 |
| Q-02 | axe で重大な違反 0 件。動きを止めるボタンがあり、`prefers-reduced-motion` のときは自動で再生しない |
| Q-03 | CSP：読み込み元は自サイトだけ。WebAssembly のために `'wasm-unsafe-eval'` だけを追加で許可する。最初のページと同時に CSP 違反のテストを入れる（開発の決まり 7） |
| Q-04 | 幅 360px で横スクロールなし。キャンバスは画面幅に合わせる |
| Q-05 | 性能の予算：WebAssembly の大きさ 100KB まで、1 ページの CSS 20KB まで、数式のフォント 60KB まで |

## 6. 検証

| ID | 検証 | 方法 |
| --- | --- | --- |
| V-01 | 二体問題（円軌道）で、1 周期後に元の位置に戻る | Rust のテスト。解析解と比較 |
| V-02 | 8 の字の解で、1 周期（約 6.326）後に初期状態に戻る | Rust のテスト（RK45、許容誤差を小さくして） |
| V-03 | 全運動量はどの積分法でも保たれる。全角運動量はリープフロッグ法で厳密に、RK45 で許容誤差の範囲で保たれる（刻み幅一定の RK4 は、接近があるとずれる） | Rust のテスト |
| V-04 | 全エネルギーのずれが、積分法ごとに想定の範囲に収まる（リープフロッグ法は長時間でも大きく増えない、など） | Rust のテスト |
| V-05 | ピタゴラスの三体問題で、最後に 1 つの天体が遠ざかっていく | Rust のテスト（既知の結果と照合） |
| V-06 | ページで WebAssembly が動き、キャンバスに描かれる。CSP 違反がない | e2e テスト |
| V-07 | Q-01〜Q-05 | e2e テスト、Lighthouse、予算の検査 |
| V-08 | 入力の検証（質量が正、位置が重ならない、有限の数）、刻み幅を細かくすると RK4 の誤差が小さくなる、数式が style 属性なしの MathML で表示される | Rust のテスト、e2e テスト |
